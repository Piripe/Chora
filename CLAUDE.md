## Project

Chora (`com.craftworks.music`, Gradle root project `MusicPlayer`) is a single-module Android app (`:app`). It streams music from Subsonic/Navidrome servers or plays from local storage. It supports phone, Android TV and Android Auto. It uses Kotlin, Jetpack Compose (Material 3, plus `androidx.tv.material3` for TV), Media3, Hilt with KSP, Ktor/Ktorfit, kotlinx.serialization and DataStore. It targets JDK 21, minSdk 24 and compileSdk/targetSdk 37.

For reference only (per the rule above, do not run these): CI (`.github/workflows/build.yml`) runs `./gradlew assembleDebug`. There are currently no unit or instrumentation tests under `app/src`. Translations are managed on Crowdin (`res/values-*`). Store metadata and changelogs live in `fastlane/metadata/android/`. The version is set by `versionCode`/`versionName` in `app/build.gradle.kts`.

## Architecture

All source code is under `app/src/main/java/com/craftworks/music/`.

**Media providers (the core abstraction).** `data/providers/media/MediaProvider.kt` is an abstract `@Serializable` class. Every backend operation goes through it: library listing via `MediaQuery.*Query` objects, playlists, favorites, ratings, scrobbling, lyrics, stream URLs, search and similar calls. Its implementations are `navidrome/`, `subsonic/` and `local/`. Each one has a `*Service.kt` (Ktorfit API) and `*Types.kt` (wire DTOs), and maps results into the shared `data/model/MediaModel` types (`Song`, `Album`, `Artist`, `Playlist`, `InternetRadioStation`, …). A provider declares what it supports through `featureFlags: EnumSet<ProviderFeature>` and its `supported*Sort` lists. The UI checks these flags instead of checking the provider type. To add a new provider, register it in the polymorphic `serializerModule` in the `MediaProvider` companion.

**Provider management.** `managers/MediaProviderManager` is a global `object`, not something injected by Hilt. It holds every configured provider and exposes `currentProvider` / `allProviders` as `StateFlow`s. It saves them to an encrypted DataStore (`providers.pb`, via `utils/EncryptedMediaProviderSerializer` + `CryptoData`). `ChoraApplication.onCreate` runs `MigrationManager.init` first and then `MediaProviderManager.init`.

**Repositories.** `data/repository/*Repository` are Hilt `@Singleton`s. They mostly delegate to `MediaProviderManager.currentProvider.value` and convert models to Media3 `MediaItem`s with `toMediaItem()`. Media items carry their provider and IDs in `MediaMetadata` extras, and `MediaMetadata.getProvider()` recovers the provider from them. Lyrics have their own source chain in `data/providers/lyrics/` (lrclib, NetEase, unison, binimum), wired in `data/di/DataSourceModule.kt`. `data/repository/MixRepository` builds the instant mix (from a song) and the album/artist radio: it asks the provider (`getSimilarSongs`, `getAlbumRadio`, `getArtistRadio`, shown when the provider has `ProviderFeature.RADIO`), completes a short result with the artist's top songs and random songs of the same genres, and uses `utils/SimilarSongs` on the library cache offline (the local provider uses it too). The Playback "Autoplay" setting makes `MusicService` append an instant mix when the last song of the queue starts.

**Crossfade and equalizer.** `player/Crossfader` overlaps songs: shortly before a song ends it hands the end of the song to a second, temporary ExoPlayer that fades it out, and moves the session player to the next song while fading it in, so the session player, queue and controllers never change. Streams transcoded on the fly can't be seeked, so the fade-out player then uses the `StreamOffset` hack (a stream that starts at the right second). `managers/EqualizerManager` generates the audio session id that both players use and attaches the device `android.media.audiofx.Equalizer` to it; it applies the Playback settings. The bands are set on their own screen (`S_EqualizerScreen`, `TvS_EqualizerScreen`, vertical sliders in `ui/elements/EqualizerBands`), opened from Playback settings. Audio offload is turned off while either is enabled.

**Playback.** `player/MusicService.kt` (`ChoraMediaLibraryService`) is a Media3 `MediaLibraryService`. It owns the ExoPlayer and session, and its `LibrarySessionCallback.onGetChildren` builds the browse tree for Android Auto. On the UI side, `player/MediaController.kt` provides `rememberManagedMediaController()` / `rememberCurrentMetadata()` for Compose. `SongHelper` provides play, enqueue and play-next helpers. `managers/TranscodeManager` and `PlaybackSettingsManager` control the stream bitrate and format.

**UI.** `MainActivity.kt` sets up phone and TV in one activity. It branches on `isTv` (from `uiMode`) to pick a TV `NavigationDrawer` or the phone layout. `NavGraph.kt` defines the routes, which are listed in `data/model/Screen.kt` and `data/NavigationItems.kt`. Screens are under `ui/screens/`, with TV-specific versions in `ui/screens/tv/`, `ui/elements/tv/`, `ui/elements/dialogs/tv/` and `ui/playing/tv/`. A UI change usually needs a matching TV change. ViewModels are `@HiltViewModel` classes in `ui/viewmodels/` and `ui/playing/NowPlayingViewModel.kt`. The Appearance "Expressive Design" setting (`AppearanceSettingsManager.expressiveDesignFlow`) is provided to the phone screens as `ui/elements/Expressive.kt`'s `LocalExpressiveDesign`; screens and shared elements branch on it, using the helpers of that file (`ExpressiveDetailsHeader`, `SettingsScaffold`, `segmentedItemShape`, …). The Home screen switches to `ExpressiveHomeScreen` instead.

**Offline.** `managers/OfflineManager` decides when the provider is unreachable; repositories then answer from the in-memory `data/cache/LibraryCache`. `player/TrackPrefetcher` keeps the upcoming queue tracks in RAM. `managers/SmartCacheManager` keeps the songs listened to the most lately on disk (ranked by `data/cache/ListeningScore`, a play count where each play halves in weight every 30 days) (files under `filesDir/smart_cache`, metadata in the SQLite `data/cache/SmartCacheDatabase`); a refresh is started from the Downloads settings and runs under the `player/SmartCacheService` foreground service. After downloading, it also saves the artists of the cached songs (picture, biography, similar artists) the playlists holding cached songs, and the folders holding them (`MediaProvider.getSongFolders`, table `cached_song_folders`), so they are browsable and searchable offline. Tracks fully pre-fetched while listening are also offered to it (`offerPrefetchedTrack`) and kept if there is room or they score higher than the lowest scored cached songs. Songs the user downloads "in the app" (`SmartCacheManager.download`, chosen in `DownloadTargetDialog` next to saving files to the device) are stored the same way with `CachedSong.manual` set: they don't count in the smart cache size and are never evicted by it. Settings › Downloads (`S_DownloadsScreen`, `S_DownloadedContentScreen`, TV versions in `TvSettingsDownloads.kt`) shows their size, lists and removes downloaded/smart-cached content, and holds the smart cache and download template settings. `player/SmartCacheDataSource` plays cached files first. `managers/OfflineScrobbleManager` stores scrobbles that failed and sends them once back online.

**Settings.** `managers/settings/*SettingsManager` are Hilt singletons. Each exposes Preferences DataStore values as `Flow`s with `suspend` setters, and writes them inside `withContext(NonCancellable)`.

**Migrations.** `MigrationManager` runs the ordered list of `migrations/Migration` classes. It tracks the version in the `MigrationStatus` SharedPreferences. When a stored-data format changes, append a new migration to that list. Never reorder the list.
